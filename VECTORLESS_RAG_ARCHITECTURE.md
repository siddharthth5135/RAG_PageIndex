# 🏗️ Vectorless RAG: Core System Architecture

Vectorless RAG is a **Context-First** retrieval system. Unlike traditional RAG (which relies on disconnected vector chunks), this system builds a **Neural Structural Map** of a document to maintain its semantic integrity.

---

## 🚀 1. The Interactive Lab (Frontend)
Located in `frontend/`, the UI is built with **Vanilla JS**, **Three.js**, and **GSAP**.

- **System Monitor (CLI):** Intercepts the backend log stream (SSE) and displays real-time "Neural Logic" updates. This allows the user to see exactly what the LLM is "thinking" during indexing.
- **Dynamic 3D Tree Renderer:** Parsed JSON data is converted into a physical 3D graph. Each node represents a document section, and its "level" in 3D space corresponds to its depth in the document's hierarchy.
- **State-Driven Workflow:**
    1. **Upload:** Selects a PDF/MD file.
    2. **Structural Indexing:** Triggers the backend parser.
    3. **Query Interface:** Unlocks only after the 3D map is rendered.

---

## 🧠 2. The Neural Parser (Backend Engine)
Located in `src/document_parser/`, the core engine is `page_index.py`.

### Step-by-Step Document Flow:
1. **TOC Extraction (`check_toc`):** The LLM scans the document's initial pages to identify an existing Table of Contents.
2. **Structural Mapping (`meta_processor`):** 
   - Translates TOC entries into physical page ranges.
   - If no TOC is found, it uses **Semantic Chunking** to "discover" headers.
3. **Accuracy Verification (`verify_toc`):** 
   - Performs a "Double-Cross check" to ensure section titles actually exist on the mapped pages.
   - If accuracy is low, it retries with corrected prompts.
4. **Recursive Deep Dive:** Large nodes (e.g., chapters) are split into sub-nodes to stay within the LLM's context window and maintain high resolution.
5. **Summarization:** Every section gets a concise description generated by the LLM. This summary is used for fast, high-quality retrieval.

---

## 🔗 3. The Retrieval Mechanism
Located in `src/agent/retriever.py`.

- **Contextual Retrieval:** Instead of just comparing vectors, the retriever uses the **JSON Structural Tree**.
- **The "Zoom-In" Logic:**
    1. The system scans the high-level section summaries.
    2. It identifies the most relevant "Parent" node.
    3. It "zooms in" to the specific sub-sections or page ranges of that node for the final answer.
- **Precision:** This eliminates the "Noisy Chunk" problem found in standard Vector RAG.

---

## 📡 4. Real-Time Communication
- **SSE (Server-Sent Events):** The backend pushes logs (`LOG:`), errors (`ERR:`), and the final graph (`FINAL:`) to the frontend over a single persistent connection.
- **Asynchronous Processing:** The parser runs in a background thread in `fastapi_server.py`, allowing the main server to remain responsive and stream logs concurrently.

---

## 🛠️ Technology Stack
- **API Framework:** FastAPI (Python)
- **3D Visualization:** Three.js / WebGL
- **LLM Orchestration:** LiteLLM (supporting Ollama, OpenAI, Anthropic, etc.)
- **Animations:** GSAP (GreenSock Animation Platform)
- **JSON Engine:** Persistent document structures are stored in `/results/`.
